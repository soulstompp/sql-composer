# Changelog

## 0.0.1

The first release on crates.io. The generator first shipped as an example in sql-composer 0.0.4,
which describes it as it was then; these are the changes since.

- **Sizes past huge** — `--size` also takes `8m`, `80m` and `800m`, the number of synthesized sets in millions. Set numbers stay distinct past nine million sets, and a set count whose inventory ids would pass `integer` is refused. Each key, statistics and vacuum build may run an hour for every two million sets unless `--build-timeout` says otherwise.
- **Builders in real cities** — Builders live on made-up streets in real cities, Natural Earth's populated places (`data/cities.tsv`, public domain), with postcodes in each country's format. The new tables `lego_cities`, `lego_postcodes` and `lego_streets` hold them, and a builder's zone is read through their street. Every purchase instant has a second and a millisecond, and its wall-clock reading is written to the millisecond.
- **A purchase reaches its set through its collection row** — A collection row names its set by `set_num`, and keeps what the builder typed, where they typed it their own way, in `typed_set_num` or `typed_name`. A purchase names its row by `(builder_id, row_no)`, and a row's copies are counted from its purchases. Every reference in the generated tables names a row its table holds, traps included.
- **Indexes, chosen with `--indexes`** — After the load, beside the primary keys: the composite indexes a DBA gives the tables for the joins between them, each led by the columns the join into its table fixes, with the columns the queries read in `INCLUDE`; two of them are expression indexes on the purchases, by month and then instant, read through `<schema>.clock(timestamptz)`, an `IMMUTABLE` function giving an instant as UTC's wall clock. Then the unique keys the tables declare, and search indexes: a `text_pattern_ops` key on postcodes, a GiST on the builders' homes by distance, and GINs on part and set names. `--indexes` takes `keys`, `composite` and `search`, as a list, or `none`. The extensions `cube`, `earthdistance` and `pg_trgm` are created before anything is written, and only for `search`, unless the database already has them in some schema; the search indexes name the schema each one is in.
- **Natural keys declared unique** — The inventory lines declare `(inventory_id, part_num, color_id, is_spare)` and the nested sets `(inventory_id, set_num)` unique. The generator writes its own lines and nested sets merged on those keys, and when the keys or partitions are asked for, a real catalogue that repeats either is refused before anything is written.
- **Object-oriented tables (`--oo-schema`, `--classes`)** — Builds the generated sets, colours and builders as class hierarchies with PostgreSQL's table inheritance, in a schema of their own: sets by the root theme of their theme, colours by their hue on a twelve-hue wheel, builders by the country of their home zone. Each row is written to its most specific class, and a placement check reads every class's CHECKs back from the catalogue after the build. `--classes` picks the hierarchies; it is refused without `--oo-schema`, and `none` is refused with it.
- **Partitioned copies (`--partitioning`, `--partition-tables`, `--partitions`)** — After the load, copies the generated tables into tables partitioned by the leading column of their natural key, one schema per method: `inheritance` (children under CHECKs below an empty parent), `range` (with a `DEFAULT` partition) and `hash`. Every run drops all three schemas before the load. A key that holds the partition column stays unique across the whole table; any other is built as a plain index and recorded in `generator_run`. A check after the build counts the rows across the partitions, reads every range back for overlaps, and sees that each key holding the partition column is unique.
- **The `paired` phase** — Packs written in pairs, their child sets chosen by release year so that the two packs of a pair hold as many pairs of consecutive years and a different number of runs of three. Each pack is listed in `trap_manifest` under O5, naming its pair, its member, its offsets and its partner's. The default patch is `natural:90,wavy:9,paired:1`.
- **Traps chosen with `--traps`** — `all` (the default), `none`, or a list. Only the traps planted at a rate and O5 can be left out, and D5 needs B2 or B5.
- **Stops before an empty catalogue or its own source** — The generator checks that `--source-schema` holds all eight real `lego_*` tables before it reads them, and names any it cannot find with how to load them. A `--schema` that names the `--source-schema` is refused, since the target schema is dropped and recreated.
- **TLS** — sqlx is built with rustls, so the generator reaches a server that requires TLS; ask for it with the URL's `sslmode`.
- **`generator_run`** — Records the definitions of the clock function and of every index built (`function_clock`, `composite_<name>`, `unique_<name>`, `search_<name>`), the partitioning, the classes and the traps, and now also `hotspot_share`, `swing_a`, `swing_b`, `swing_period` and `upto_phase`. `--freeze` is recorded as `freeze`; it was `freeze_reference_tables`.
- **Help** — Every flag has help text, and `--help` names the program by its own name.
- **Tests** — The test comparing the LEGO example's index migration with the generator's indexes reads the migration when it runs, and passes, saying so, where the file is absent, so the packaged crate's tests build.
